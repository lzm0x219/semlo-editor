# 保存与恢复内容

semlo-editor 不提供存储服务。应用需要从编辑器获取内容，将它保存到自己的存储，并在下次打开时传回编辑器。

## 选择保存格式

每次内容变更时，`onChange`（Vue 中为 `change`）收到一个 `EditorSnapshot`：

| 字段   | 用途                           | 注意事项                                 |
| ------ | ------------------------------ | ---------------------------------------- |
| `json` | 保存和恢复可编辑文档           | 推荐作为编辑内容的存储格式。             |
| `html` | 在其他页面展示或作为 HTML 输入 | 公式等内容脱离编辑器展示时需要额外处理。 |
| `text` | 纯文本处理，如摘要或索引       | 不包含完整文档结构，不能用于无损恢复。   |

也可以随时调用 `editor.getSnapshot()` 获取当前快照。数据表等结构化内容会随文档 JSON 和 HTML 保存；图片、附件与音视频通常保存的是地址，文件本身由应用的上传服务管理。

部分编号列表转换为正文或标题时，内容会保存来源标识，以便之后恢复原编号。旧内容的快照不会因读取添加该标识，但底层 Tiptap 的 `editor.getJSON()` 可能在正文或标题上返回值为 `null` 的属性。含新标识的内容可能无法被旧版严格 JSON 读取器接受；过滤自定义 HTML 属性也会丢失来源。详见项目 ADR 0002。

首次复制标题段落链接会将标题标识写入快照并触发 `onChange`；应用须保存该快照，并在链接打开后加载同一文档。链接定位、只读旧标题和旧版读取器的限制见[标题与大纲](/text-and-blocks#标题与大纲)。

在根级正文、顶层引用、顶层高亮块、折叠块正文或根级普通表格直接单元格的空段落键入 `/` 发起查询后，仍活跃的查询文字不会进入 `getSnapshot()` 或 `onChange` 的 JSON、HTML 和纯文本；折叠正文内的高亮块也采用这一规则。编辑区继续显示查询，光标和撤销历史保留。按 `Esc`、从查询移开选区、将焦点从编辑区及其斜杠菜单转到宿主控件或另一个编辑器，或切换浏览器标签时，查询转成普通正文，并通过变更回调通知应用保存。在斜杠菜单及其表格、分栏子菜单之间移动焦点不会退出查询。

直接销毁仍有活动查询的编辑器不会自动提交查询；如果需要保存这些输入，应先退出查询，再获取快照并销毁实例。

已有文档、粘贴或程序插入的 `/p` 不会仅因文字形似查询而被移除。受控组件回写相同的保存快照时，编辑器保留当前活动查询；传入不同文档仍会替换内容。标题、普通列表和折叠标题中的斜杠沿用正文规则。相关浏览器及三框架样本已有回归；语雀根级正文、引用、高亮块和普通表格直接单元格的保存路径已有对照，其他深层嵌套、完整命令及真实输入法仍待核验。

## 示例：保存在当前浏览器

以下示例使用 `localStorage` 展示完整流程。它只适合本机演示：清除站点数据会删除内容，也不会跨设备同步。

```html
<div id="editor"></div>
<button id="save" type="button">保存</button>
```

```ts
import { createEditor } from "@semlo-editor/core";
import type { EditorContent } from "@semlo-editor/core";
import "@semlo-editor/core/style.css";

const key = "semlo-editor-document";
const host = document.querySelector<HTMLElement>("#editor");
const save = document.querySelector<HTMLButtonElement>("#save");
if (!host || !save) throw new Error("缺少编辑器或保存按钮");

let content: EditorContent | undefined;
try {
  const stored = localStorage.getItem(key);
  if (stored) content = JSON.parse(stored) as EditorContent;
} catch (error) {
  console.error("无法读取本地文档", error);
  throw error; // 停止初始化，避免用空文档覆盖原始数据。
}

let editor: ReturnType<typeof createEditor>;
try {
  editor = createEditor({
    element: host,
    content,
    onError: (error) => console.error("编辑器错误", error),
  });
} catch (error) {
  console.error("无法恢复文档，请保留原始数据并处理格式", error);
  throw error;
}

save.addEventListener("click", () => {
  try {
    localStorage.setItem(key, JSON.stringify(editor.getSnapshot().json));
  } catch (error) {
    console.error("保存失败", error);
  }
});

// 页面卸载时调用 editor.destroy()，并移除应用自己注册的监听器。
```

实际应用可以在 `onChange` 中安排保存，但应自行处理保存失败、写入顺序和未完成的请求。不要假设变更回调意味着数据已经持久化。

## 恢复或替换内容

首次创建时传入 `content`；已有实例可以使用 `setContent`：

```ts
editor.setContent(savedDocument);
```

创建编辑器时，JSON 中无效的节点结构、未被当前扩展声明的节点或标记及其属性会导致初始化抛出异常；失败时编辑器会清理已创建的资源。请捕获异常并保留原始数据，检查数据格式及所需扩展后再重试。`onError` 不负责报告这类初始化异常。普通 HTML 初始化仍按现有规则宽松导入，未识别的结构或属性可能被忽略，导入结果应由应用确认。

当前内容没有统一的格式版本或自动迁移机制。应用应保存原始内容，并自行记录所用编辑器版本、扩展和备份；升级后先在副本上验证读取、编辑及再保存。不要假定当前版本可以识别或无损处理未来版本的所有内容。

数据表的 JSON 和 HTML 载荷会单独校验：载荷损坏、超出容量，或包含当前实现无法保留的嵌套数据时，初始化会抛出异常。HTML 中被识别为数据表的内容也遵循这一规则。保留原始内容并处理错误后再重试，不要用空数据表覆盖它。

`setContent()` 不触发 `onChange`；应用主动写入后需要保存时，应自行安排保存。无效内容会通过 `onError` 报告，原文档保持不变。语义相同的文档经过规范化比较后不会重复替换。

如果应用在同一编辑器事务提交前同步替换不同内容，`setContent()` 会抛出 `ReentrantTransactionError`。应等待当前事务结束后，依据当前状态决定是否替换；如果编辑器在事务提交前被销毁或卸载，事务会抛出 `TransactionAbortedError`。错误处理和底层集成边界见[控制器 API](/controller-api#editor)。

切换到另一篇文档时，先处理当前文档的保存，再销毁并重新创建编辑器。框架中可按文档 ID 重新挂载组件，避免沿用上一篇文档的撤销历史，详见[框架适配](/frameworks#更新配置与切换文档)。

## 标题折叠视图状态

默认情况下，可编辑文档的标题折叠状态写入 JSON 和 HTML，并通过 `onChange` 通知应用保存；应用重载已保存的内容后会恢复折叠。点击标题折叠或展开、从大纲跳转或查找正文时自动展开的标题可撤销和重做。标题链接及查找标题触发的展开不增加撤销步骤。只读模式可临时展开或折叠，但不会修改文档；重新载入后仍使用保存的状态。粘贴标题时会清除其折叠标记，避免隐藏目标文档中的既有内容。

旧内容不含折叠标记时默认展开，不会因载入而迁移。新标记为 JSON 的 `semloEditorHeadingFolded` 和 HTML 的 `data-semlo-editor-heading-folded`；旧版严格 JSON 读取器可能拒绝该属性，过滤自定义 HTML 属性的宿主可能丢失状态，脱离编辑器展示的静态 HTML 也不会自动隐藏内容。

若应用有明确的文档 ID 和内容版本，也可以提供适配器独立保存折叠位置。配置适配器后以其结果为准，折叠不改变文档 JSON、HTML 或 `onChange`；只读模式同样可使用该适配器。文档若已有默认模式写入的折叠标记，适配器不会改写该标记；之后脱离适配器载入时仍会使用文档中的标记。

```ts
import { captureHeadingFoldRevision, createEditor } from "@semlo-editor/core";
import type { EditorContent, HeadingFoldPreferences } from "@semlo-editor/core";

// ID 和版本由应用提供；不同内容必须使用不同版本。
const documentId = "document-42";
const revision = "revision-7";
const key = (id: string, version: string) => `heading-fold:${JSON.stringify([id, version])}`;

const editor = createEditor({
  element: host,
  content,
  headingFoldPreferences: {
    documentId,
    revision,
    load: (id, version) => {
      const value = localStorage.getItem(key(id, version));
      return value ? (JSON.parse(value) as HeadingFoldPreferences) : null;
    },
    save: (id, version, state) => localStorage.setItem(key(id, version), JSON.stringify(state)),
  },
});

// 由应用实现：原样保存 JSON，并返回与该内容对应的新版本。
declare function saveDocument(content: EditorContent): Promise<{ revision: string }>;

async function saveCurrentDocument() {
  const capture = captureHeadingFoldRevision(editor);
  if (!capture) throw new Error("编辑器不可用或未配置标题折叠存储");
  const saved = await saveDocument(capture.snapshot.json);
  if (!capture.commit(saved.revision)) console.error("标题折叠状态未完成迁移");
}
```

宿主必须保证相同 ID 和版本始终对应相同的规范化文档；库无法识别所有错误复用的版本。内容改变后，旧版本的折叠写入会停用。`captureHeadingFoldRevision()` 同时捕获内容和折叠状态；宿主须原样保存 `capture.snapshot.json`，确认成功后再以返回的版本调用 `commit()`。如果保存期间内容没有变化，提交会绑定新版本，之后折叠操作继续保存到该版本；如果内容已改变，只为已保存的快照记录捕获时的折叠状态，当前编辑器继续等待下一次保存。较早捕获的提交不会覆盖已提交的较新捕获。

未配置适配器或实例不可用时，捕获返回 `null`。无效版本、重复提交、过期提交、实例已卸载或销毁、存储失败时，`commit()` 返回 `false`；某些中断发生在存储调用之后，因此返回 `false` 不保证没有发生存储写入。不同内容必须使用不同版本；库会拒绝部分显然错误的旧版本复用，但应用仍须负责版本正确性和文档保存顺序。`load` 和 `save` 是同步接口；若宿主在 `save` 中启动异步写入，还需自行处理失败和写入顺序。同步存储失败时，内存中的折叠状态仍可使用。此接口不定义跨用户或协作同步行为。

## 在编辑器之外展示 HTML

使用 `getSnapshot().html` 获取 HTML。公式输出保留 TeX 源码和标记，脱离编辑器后需要接入方渲染；字体名称随文档保存，但字体文件不会随文档提供。直接调用底层 Tiptap 实例的 `getHTML()` 或 `commands.setContent()` 不会处理 semlo-editor 的文档级字体包装信息。

展示来自不可信来源的 HTML 时，应按应用的安全策略处理；编辑器的输出并不替代展示端的安全处理。其他内容格式与界面状态的区别见[核心概念](/concepts)。
