## 图片

配置 `uploadImage` 后，可通过插入按钮、粘贴或拖拽上传图片。选中后可旋转、裁剪，并设置宽高、比例、样式、描述、链接和对齐；悬浮工具提供预览、删除和复制，可在同一文档的正文图片之间切换。描述可隐藏和恢复，不计入正文文本。也可通过图片地址插入；上传服务和地址的长期可访问性由应用负责。

裁剪和旋转保存在文档中，不会替换原图文件；可以再次调整裁剪范围或还原图片。预览和导出的 HTML 显示变换后的范围，JSON / HTML 保留相关设置。

通过编辑器操作会记录变换后的宽高。若应用自行构造包含裁剪或旋转的 JSON，应同时提供宽高；否则静态 HTML 无法可靠确定图片外框。

图片可以与文字放在同一段落；设置图片对齐时，整个段落会一起对齐。

上传回调示例和失败处理见[上传与提及](/uploads-and-mentions)。保存文档时保存的是引用信息，图片文件不会自动打包进文档快照。

同一批粘贴或拖入的图片按顺序上传。文档替换、销毁或切换只读后，尚未开始的图片不会继续调用上传回调；已开始的上传会收到中止信号，网络请求需要由应用使用该信号取消。

## 图册

插入图册后可上传多张图片，使用轮播、缩略图轮播或平铺布局。设置界面支持调整顺序、编辑每张图片的标题与链接、删除图片和预览。确认设置后保存，取消可放弃设置中的修改；直接删除图册图片可使用编辑器撤销。

图册使用 `uploadImage`。多张图片上传完成的先后顺序不会改变选择时的顺序。文档替换、销毁或切换只读等情况下，过期的上传结果不会写入新文档，并会中止相关上传信号。

## 附件与音视频

附件、本地音频和本地视频通过插入面板选择文件，使用同一个 `uploadAttachment` 回调。回调应返回之后仍可访问的地址。编辑器内的音频卡片显示文件名、大小、进度和时间；视频播放器提供播放、进度、时间、音量、全屏及画中画入口，悬停进度条可查看对应时间，编辑时可下载原文件。音视频都支持 0.5 到 2 倍的六档速度，只读时也可使用播放控件；这些操作不写入文档或撤销历史。画中画和全屏取决于浏览器支持，跳转取决于媒体可用的时间范围，文件服务应正确处理 HTTP Range 请求。导出 HTML 使用浏览器原生媒体控件；能否播放取决于浏览器、媒体格式和返回地址。

音频卡片提供原文件下载和“阅读页可下载”设置。设置随 JSON / HTML 保存并支持撤销；关闭时只读编辑器隐藏下载入口，导出的原生播放器使用 `controlslist="nodownload"` 提示浏览器。这个设置只控制界面和浏览器提示，不能限制直接访问文件地址；接入应用必须在文件服务端执行实际权限控制。旧音频没有该设置时保留原有内容格式，带新设置的 JSON 可能被旧版严格读取器拒绝，旧版 HTML 读取器也可能丢失该设置。

编辑时单击附件名称会选中附件，工具提供标题、卡片和嵌入三种显示模式，以及预览、下载和“阅读页可下载”设置。标题随文字排列，卡片显示整行文件信息；嵌入模式在正文内加载应用提供的阅读页，可拖动底部手柄调整高度，切换和一次高度拖动均可撤销。只读时仍保留已保存的显示模式，单击附件名称或按 Enter 可在新页面预览。

独立预览默认打开原文件；应用可通过 `resolveAttachmentPreview` 提供自己的阅读页。PDF、Office 原文件地址在嵌入模式下显示“在新页面打开”，需要应用提供可嵌入的阅读页才能在正文内阅读。阅读页使用不透明源沙箱，应用页面不能依赖编辑器的同源权限；服务器还需允许页面被嵌入。接入示例和失败规则见[附件预览](/uploads-and-mentions#附件预览)。

显示模式和预览高度随 JSON / HTML 保存，阅读页地址不进入内容。旧附件默认按标题显示，不会自动加载嵌入页。新增的 `displayMode`、`previewHeight` 在 JSON 中默认为 `null`；不支持这些属性的旧版严格解析器可能拒绝新快照，混用版本前需验证。无法识别的设置会保留并提示，不能继续改写显示设置。

下载始终使用原文件地址，是否下载及文件名由浏览器和服务器响应决定。“阅读页可下载”随 JSON / HTML 保存并可撤销，关闭时只读卡片和嵌入视图隐藏下载入口；旧附件默认保留入口。此设置不能限制直接访问原文件、静态 HTML 链接或宿主阅读页中的下载按钮，接入应用必须在文件服务及阅读页中实施权限。旧附件的缺省设置不写入公开快照；带新设置的 JSON 可能被旧版严格读取器拒绝，旧版 HTML 读取器也可能丢失该设置。组件不包含远程 Office 转换。

已有内容中不符合地址规则的附件或音视频地址会随 JSON 和 HTML 保留，但不会成为可点击链接或播放器地址；应由应用修复来源后再使用。较早版本不一定能保留新版 HTML 的这些原始信息，混用版本保存时需另行验证。

## 第三方嵌入

使用插入面板选择对应服务，粘贴受支持的 HTTPS 链接并确认；是否可以加载和播放取决于第三方服务及访问环境。嵌入可转换为普通链接；哔哩哔哩、优酷、CodePen、Canva 和金数据的直接链接使用校验后的播放器或嵌入地址。Canva 保留 `embed`，金数据保留经过校验的嵌入参数；保存的规范地址及“打开链接”仍按各服务原有规则处理。配置 `resolveEmbedMetadata` 后，也可转换为书签卡片。

Figma 也接受经过校验的旧式 `figma.com/embed?embed_host=…&url=…` 地址，嵌入和直接转链接保留该包装地址。普通文件或原型链接仍按原有规则规范化。Figma 继续支持这种 Embed Kit 1.0 文件嵌入，见[官方说明](https://developers.figma.com/docs/embeds/embed-kit-2.0/)。

嵌入只接受已支持服务的链接格式，不能作为任意 iframe 的插入接口。应用应根据自身隐私和内容策略决定是否使用第三方嵌入。

`resolveEmbedMetadata(url, { signal, canonicalUrl })` 由应用提供书签标题、描述和图标。`url` 是经服务规则校验并生成的嵌入地址，`canonicalUrl` 是可选的规范原链接；应用负责元数据请求及网络策略，并应在 `signal` 中止时取消请求。书签节点在视图更新中被修改或移除时，旧结果立即失效，`signal` 的中止通知可能延迟至下一微任务。没有配置回调时，书签转换不可用。
