# PlantUML 隔离边界

当前 `@plantuml/core` 依赖主线程 DOM、Canvas 和页面全局状态。Semlo 检测到宿主已占用相关状态时会拒绝渲染，并在清理时保留宿主后来修改的属性；但这不能隔离渲染期间才启动的宿主代码。引擎同步阻塞或一直不返回时，当前队列也可能停住。

隔离原型在真实 Chromium 中把引擎放入 Worker，并补齐 XML DOM、Canvas 测量及 sprite 编码；已验证实例销毁和超时能终止对应任务，另一实例继续运行，宿主同名属性不被读取。选定的外部 include 和图片输入没有发出网络请求。引擎输出仍必须经过现有 SVG 清理；这些样例不是完整安全审计。

Worker 不自动继承宿主动态字体。原型通过主线程测量后重新运行引擎，使 9 个内置模板及 21 组文字布局样例与当前主线程结果一致；字体变化可产生新的测量请求，因此需要有界重试和明确失败。兼容现有部署的多轮方案在本机冷运行约 370–520 毫秒，Rsbuild 消费产物的 Worker 主块约 5.34 MB；当前主线程热运行约 3–29 毫秒。这些只是所测输入的本机样本。

复用 Worker 可降低延迟，但字体加载后引擎内部缓存可能沿用旧度量；动态导入新模块恢复了结果，却造成模块实例和内存持续增长。另一个带测量核验的复用原型需要 `SharedArrayBuffer` 和跨源隔离，会改变宿主的 COOP/COEP 部署要求，还依赖引擎未承诺的内部行为。输入和消息上限也不能保证浏览器进程内的硬内存隔离。

因此该原型尚未接入默认路径。后续若继续，应先确定部署与字体契约，验证更多语法、CSP、浏览器、生产打包、取消和资源上限，再与现有渲染结果及实际设备性能对照。
