# 内部架构

本文面向维护 Semlo 的开发者。公开入口仍是各包的 `src/index.ts`；下列内部路径可以随实现调整，不作为接入方的 API。

## 工作区和核心目录

- `packages/core`：编辑器、默认界面、内容格式及接入能力。
- `packages/react`、`packages/vue`、`packages/solid`：对应框架的组件适配。
- `demo`、`docs`、`tests`：体验页、文档站和回归测试。

`packages/core/src` 按职责组织：

```text
editor/         编辑器组合、实例生命周期、扩展注册和内容读写
features/       文字、列表、表格、数据表、媒体、插入等功能
integrations/   每实例宿主能力绑定与上传生命周期处理
platform/dom/   已被多个功能使用的 DOM 和弹层基础能力
runtime/        事务、选区同步、历史和通用清理
shared/         现有功能共同使用的日期和缩进规则
styles/         编辑器基础样式及有序样式清单
ui/             默认工具栏、查找、目录和其他界面
index.ts        核心包公开导出
```

组合层负责装配功能与默认界面；功能模块负责自己的文档规则和视图资源。适配器通过核心包接入，不能自行维护第二份文档状态。共享模块应有真实的多个使用者，不为了减少文件数量而把无关功能放在一起。

## 生命周期与内容

`editor/create-editor.ts` 创建编辑器并接入功能。`editor/lifecycle.ts` 协调实例及视图资源；`controlled-editor.ts` 处理宿主直接销毁底层编辑器时的清理。销毁前先标记状态，关闭资源登记后再执行释放回调，以处理回调重入和清理异常。初始化失败与正常销毁的顺序分别由组合层提供，修改时应同时验证两条路径。

内容初始化、严格解析、替换、快照和 HTML 输出位于 `editor/content/`。JSON 在解析前检查当前 schema 声明的节点和标记属性，并在解析时校验内容结构；创建失败抛出异常，替换失败通过 `onError` 报告并保留当前文档。普通 HTML 初始化仍宽松解析。内容替换先校验并比较文档，再通知旧视图和异步任务失效；HTML 输出按文档字体、有序列表和标题编号的现有顺序处理。变更时保持节点名、属性及已有 JSON/HTML 格式，并验证受控回写、撤销、旧异步结果和宿主自定义扩展。

数据表载荷在 JSON、HTML 解析及输出时检查容量和可保留性：允许补齐缺省值，拒绝损坏、超限或会被归一化丢弃的内容；HTML 数据表不因普通 HTML 宽松解析而降级为空表。编辑操作在提交前检查容量，失败时保留已提交内容、提示错误并报告 `onError`；文件选择数量超限时不调用上传服务。数据表的底层 Tiptap 节点必须携带有效数据，插入空载荷节点不再生成默认表。

结构化内容的共同底线是：不能把已接收的损坏内容、超限值或未知字段静默替换、截断后保存。功能可按自身约束选择在写入前拒绝并报告，或保留原始数据、显示不受支持并限制相关操作；安全展示只使用经过校验的投影。修改时分别检查 JSON、HTML、编辑写回和撤销，不把一种格式的检查当作其他格式的证明。现有内容类型仍需逐项核查，不能仅凭这条原则声称所有类型均已完整覆盖。

数据表、画布等现有载荷没有统一的显式版本字段，不能假定旧文档已经携带版本。未来需要演进时，应先按内容类型定义旧载荷识别、迁移和失败恢复，并保留原始数据；未知的未来版本应拒绝写入或保留为不可编辑内容。增加版本字段前须验证未版本化数据的读取、编辑、撤销和 JSON / HTML 往返；目前没有通用版本迁移机制。

默认工具栏由 `ui/toolbar/default-toolbar.ts` 分阶段装配和刷新，`read-state.ts` 读取选区、文字样式和对齐状态。浮动工具栏由 `ui/toolbar/bubble.ts` 管理容器、定位扩展和默认控件；`floatingToolbar` 工厂可替换控件，复用选区显示规则和链接弹层。组合层负责将控制器、选区同步、事务/只读订阅及实例生命周期交给两个工具栏工厂，并在初始化失败时清理；关闭或自定义主工具栏时不创建默认主工具栏，关闭浮动工具栏时不创建浮动容器，自定义浮动工具栏时不创建默认浮动控件。`toolbar` 和 `floatingToolbar` 可分别配置，未指定后者时保持原有 `toolbar` 开关行为。查找和格式刷快捷键独立装配；没有默认主工具栏时，高亮快捷键使用默认颜色。选区同步位于 `runtime/selection-sync.ts`。链接和图片地址弹层由 `editor/url-session.ts` 管理，语雀内容选择弹层由 `features/references/yuque-content-session.ts` 管理；组合层负责提供实例状态与弹层装配。插入命令、最近使用记录和菜单会话位于 `features/insertion/`。主工具栏、斜杠和块操作入口共享功能规则，但各自保留原有选区、焦点和失效时机。

浮动工具栏定位时避让同一实例可见的主工具栏，在选区变化、视口调整和相关容器滚动时更新位置；滚动监听仅在浮动工具栏显示时存在，并在隐藏或销毁时清理。未配置主工具栏时不增加避让边界。

加粗命令及选区状态位于 `features/text/bold-command.ts`，主工具栏、浮动工具栏和快捷键使用同一规则；自定义界面可从核心公开入口读取状态并执行命令。仅标题选区禁用加粗，跨标题与其他文本时保留标题格式。选区同步与焦点仍由调用入口按交互方式处理。

标题和正文样式的共享命令与菜单状态位于 `features/heading/style-command.ts`，转换实现和选区分类分别位于 `conversion.ts` 与 `selection.ts`。默认菜单显式设置样式，快捷键和体验页按钮切换样式；折叠卡片跨区时菜单禁用，但快捷键仍沿用原有正文转换行为。

链接状态、地址校验和编辑会话位于 `features/references/link-command.ts`，默认弹层、快捷键及自定义工具栏共用占位和写入规则。会话持有目标选区，在文档变更、只读、卸载或销毁时失效；调用方负责关闭未完成会话。

列表命令及状态位于 `features/list/list-command.ts`，默认工具栏和自定义界面复用待办、无序及有序列表转换规则；不支持安全转换的复杂选区保持原内容。折叠卡片标题选区的分类位于 `features/blocks/details-selection.ts`，供列表状态和工具栏共同使用。

`integrations/bindings.ts` 为每个编辑器保存当前宿主能力并识别变更；组合层按既有顺序通知相关功能，功能自身负责使旧请求和视图失效。数据库表格、图册/看板、日历和图表视图位于 `features/database/views/`；单元格连续输入和输入法会话由 `edit-session.ts` 管理。`features/database/interactions/` 按弹层会话、单元格、字段、筛选分组排序和视图设置组织界面交互，节点视图负责装配和协调统一的事务写入。画布的数据、几何、导出、绘制、指针会话、控件和剪贴板交互分别位于 `features/drawing/canvas/`，视图通过节点视图提供的当前节点和文档代次校验操作是否仍有效。

`integrations/update-coordinator.ts` 维护每实例的待通知状态、失败重试和同步重入顺序；组合层只提供具体能力的装配与失效操作。数据表的记录变更基线和元数据更新位于 `features/database/record-change.ts`；日历月份和分组折叠状态由每个节点视图的 `view-state.ts` 管理，不写入文档。画布及思维导图保留无法识别的展示属性，不能安全解释时显示提示并停止相关编辑。

大表测量、复现入口和窗口渲染约束见[数据表性能边界](database-performance.md)；PlantUML 的全局状态、Worker 隔离试验及未闭合的兼容问题见[PlantUML 隔离边界](plantuml-isolation.md)。

## 样式和测试

`styles/bundle.css` 是组件包和体验页共用的有序样式清单，`styles/style.css` 继续维护其中的基础样式顺序。`styles/katex.css` 是官方 KaTeX 样式的受控副本，将公式计数器限制在编辑器内；更新 KaTeX 时需同步副本并通过 CSSOM 回归检查。`packages/core/scripts/copy-style.ts` 按清单拼接样式，并将公式字体路径改写为包内路径；`demo/editor.css` 直接引用同一清单。调整样式时应保留级联、字体和许可证，并比较构建产物。

测试按功能、工具栏、生命周期和适配器归组。共享 fixture 按用途存放在 `tests/fixtures/`，专项配置位于 `tests/config/`；`tests/browser/cases/` 存放 `browser-*.ts` 场景，由 `tests/browser/browser-regressions.ts` 发现并分配给四个测试文件。`tests/browser/checks/` 中的独立浏览器检查由 `standalone-checks.test.ts` 纳入标准测试，并在临时目录构建所需的画布 fixture。静态资源的源文件放在 `tests/fixtures/assets/`，构建后仍使用原来的浏览器访问路径。移动场景或 fixture 时，须同步检查发现规则、类型配置、构建入口及静态资源路径，确认测试集合没有减少。

CI 将完整回归分成八片，每片使用两个 worker；手动运行 CI 时可选择 `profile`，为各片收集 Rstest 耗时追踪和摘要。常规运行不启用追踪，避免增加采集开销。

## 命名与注释

目录和普通文件使用小写 kebab-case；测试使用现有的 `.test.ts` 后缀。类型、接口、类和扩展使用 PascalCase，函数、方法和变量使用 camelCase。创建、挂载、打开、解析和归一化分别使用 `create`、`mount`、`open`、`parse` 和 `normalize` 等准确表达行为的动词。

新写或实质修改的注释以简体中文说明原因和约束，重点记录兼容格式、资源所有权、异常、重入和异步失效；不逐行复述代码。已有准确的英文注释不必仅为统一语言而改写。包名、公开导出、节点名、文档属性、CSS 类、事件、PluginKey 和存储键不能因内部命名调整而改变。
