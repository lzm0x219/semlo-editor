后续真实鼠标探针发现当时的候选对软换行边界的判断错误：同一模型位置在两侧亲和性下分属不同行，点击第一行末尾后按 Shift+End，候选曾选中并删除第二行开头。所测普通和编号 H3 均可复现；一次撤销恢复。成对点击探针中，第一行末与第二行首得到相同的 DOM 节点和偏移，折叠 Range 的包围矩形也相同，不能单凭它们推断光标所在的视觉行。ProseMirror 的指针选区事务标记也可由宿主通过公开 API 生成，不能单独作为浏览器指针操作的证明。该版本未合入；后续处理见下文，语雀对应行为尚未验证。

进一步在本地用真实鼠标点击普通和编号标题的软换行两侧，截图均显示光标分别位于上行末和下行首，但两侧的 DOM 节点、偏移和编辑器位置相同。在所测样本中，`Selection.modify` 可按当前视觉侧得到不同结果；然而将上行末的节点与偏移原样恢复后，光标可跳到下行首。隔离宿主实验也观察到事务被拒绝后出现同类跳行，即使 DOM、编辑器选区和文档均与操作前相同。因此不能仅靠恢复节点和偏移撤销该探针的副作用，该实验方案未接入。结果只反映本机 Chromium 样本，并非语雀直接对照。

## 复现浏览器验证

需要 mise 和 Playwright 可使用的 Chromium。首次运行若提示缺少浏览器，可先执行 `mise exec -- pnpm exec playwright install chromium`。在项目目录执行：

```sh
mise install
mise exec -- pnpm install --frozen-lockfile
mise exec -- pnpm test
mise exec -- pnpm typecheck
mise exec -- pnpm lint
mise exec -- pnpm format:check
```

Rstest 会构建浏览器测试产物，在随机本地端口启动隔离服务，并在测试结束后关闭服务。已有浏览器脚本通过 Rstest 运行，新测试使用 `@rstest/playwright` 编写。只运行某个测试文件时，先构建测试产物，例如：

```sh
mise exec -- pnpm build:browser-test
mise exec -- pnpm test:run tests/features/insertion/slash-keyboard.test.ts
```

`build:browser-test` 会将实际构建的组件库及测试所需依赖打包到 `.browser-test/`，仅供本地浏览器回归使用。测试使用临时本地服务和隔离浏览器上下文，不连接语雀账户或外部上传服务。键盘测试使用 macOS 的 `Meta`，其他系统需调整对应快捷键。
